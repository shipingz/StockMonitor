# ADR-0007: 消息格式与推送策略 — markdown、合并推送、超限拆分

- 状态：**已确认**
- 日期：2026-08-15（讨论确认）

## 背景

需要确定企业微信机器人 Webhook 的消息格式、内容字段与多信号推送策略。

## 事实约束（已查证）

- 企业微信机器人 Webhook：text ≤2048 字节，markdown ≤4096 字节；每分钟最多 20 条消息。
- 企业微信 markdown 为阉割版：支持标题/加粗/引用/列表等基础排版，**不支持表格、图片、超链接**。
- 本项目 16 次/天触发，远低于 20 条/分钟限制；限制主要来自单条长度。
- 中文 UTF-8 编码为 3 字节/字符，长度校验须按**字节**计算。

## 决策

1. **格式：markdown**。信号消息带标题与关键数字加粗，醒目易读。
2. **内容字段**（单条信号条目）：
   - 股票名 + 代码（如 `贵州茅台（600519）`）
   - K线时间戳（如 `K线时间: 10:00`）——兼作 ADR-0005 边界重复场景的人工辨识手段
   - 收盘价、MA60 值、偏离百分比
   - 信号说明（`收盘价上穿 MA60`）
   - 不含涨跌幅（避免额外请求）
3. **多信号合并**：一轮运行中多只股票同时上穿时，**合并为一条消息**（一个信号列表），减少刷屏与 webhook 调用。
4. **超限拆分护栏**：合并后的总字节数若超过安全阈值（markdown 上限 4096 字节，取安全阈值 ~3800 字节留余量），**拆分为多条推送，条数尽量少**：
   - 按「贪心打包」拆分：按顺序将信号条目累积进当前消息，直到加入下一条会超过安全阈值，则开启新消息。
   - 单条信号自身超限（极端情况）：截断并提示（实际不可能发生，字段固定且很小）。
   - 所有消息的 K 线时间戳保留，便于人工对照。
5. **失败通知（可选待定）**：抓取失败/严重延迟的告警消息是否也走该 webhook，见 ADR-0008 待讨论。

## 后果

- 正常情况每轮运行最多 1 条 markdown 消息；极端情况（信号极多）拆分为少量几条。
- 消息含 K 线时间戳，配合 ADR-0005 无状态设计，重复推送可人工识别。
