# ADR-0005: 状态设计 — 无跨运行状态，接受边界重复/漏检

- 状态：**已确认**
- 日期：2026-08-15（讨论确认）

## 背景

GitHub Actions 每次运行都是全新容器，无记忆。需要决定「同一信号只推一次」靠什么保证。

## 选项

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 状态文件提交回仓库 | 推送成功后把 (股票, K线时间戳) 写入 `state/*.json` 并 git commit | 不重不漏 | 引入 commit 触发风险、并发 push 冲突、token 权限一整串复杂度 |
| B. Actions Cache | 用 `actions/cache` 存状态 | 实现简单 | cache 是尽力而为，可能 miss/被清理 → 重复推送，对正确性场景不可靠 |
| C. 外部存储（Gist/KV） | 第三方持久化 | 可靠 | 多一个故障点和密钥 |
| D. **无状态（采纳）** | 调度上保证同一K线只被一次运行看到（ADR-0003 精确对齐）；边界情况接受偶发重复/漏检 | 零状态零复杂度；与参考项目理念一致 | 运行失败即漏检；极端延迟下偶发重复 1 条 |

## 决策

采用 **D：无状态**。前提是 ADR-0003 的「收盘后 3 分钟精确对齐」调度——同一根K线正常只被一次运行看到，去重由调度频率天然保证。

- 不做任何跨运行持久化（无状态文件、无 git commit 回写、无 cache）。
- **推送成功即视为完成**，失败即丢弃（记录日志），不重试不补偿。
- 消息内容携带 K 线时间戳（如 `K线时间: 10:00`），作为边界重复场景下的人工辨识手段。
- 护栏（ADR-0003）：严重延迟（最新K线距收盘 >15 分钟）时跳过推送并记录告警，作为健康监测。

## 后果

- 代码与运维复杂度最低；无「commit 触发循环」「并发 push」「token 权限」问题。
- 接受两个边界：运行失败 → 漏检该根K线；job 延迟 >12 分钟跨过K线边界 → 偶发重复 1 条或漏 1 根。
- 若未来不能容忍边界情况，可事后引入状态文件（本 ADR 的方案 A），与现有代码解耦。
