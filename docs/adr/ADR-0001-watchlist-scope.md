# ADR-0001: 监控范围 — 自选股列表（≤50只），而非全市场扫描

- 状态：**已确认（2026-08-15 修订：列表存放位置从仓库文件改为 Repository variables）**
- 日期：2026-08-15（讨论确认）

## 背景

需要实时监测「15分钟K线收盘价超过 MA60」信号。信号计算依赖每只股票独立的 15 分钟历史K线（至少 60 根），且需要定时重复抓取。

## 选项

### A. 全市场扫描（约 5400 只）

- 每只股票至少 1 次 `stock_zh_a_hist_min_em` 请求 → 每轮检查 5000+ 次请求。
- 单轮运行 30~60 分钟，远超 15 分钟K线节奏，且极易触发东方财富限流（HTTP 429）。
- GitHub Actions 免费额度（2000 分钟/月）会被快速耗尽。
- 全市场信号量大，企业微信推送会刷屏。

### B. 自选股列表（≤50只）

- 每轮检查 50 次请求，轻量并发下 30~90 秒完成。
- 请求量小，429 概率低；配合指数退避重试足够稳定。
- 推送消息量可控，用户只关注自己关心的股票。
- 代价：需要维护股票列表配置文件，新增/删除股票要改配置。

## 决策

采用 **B：自选股列表，上限 50 只**。

- 股票列表存放在 **GitHub Repository variables `STOCK_LIST`**（逗号分隔的纯 6 位代码，如 `600519,000001,300750`），而非仓库文件（2026-08-15 修订，见 ADR-0009）。
- 脚本每轮用 `stock_info_a_code_name()`（1 次请求）自动匹配代码→名称，并校验代码存在性；查不到的代码推告警。
- 上限 50 只是软约束：超过时脚本应告警而非静默截断。
- 名称不手工维护：运行时自动匹配，避免人工写错名。
- **股票类型边界**（Q8 确认）：
  - **北交所不纳入**：数据源支持不稳 + 15分钟历史数据可能不足 60 根；仅支持沪深（主板/创业板/科创板）。
  - **ST/*ST 不设隐式过滤**：用户自选股列表自行决定，脚本不拦截。
  - **新股/数据不足 60 根**：跳过该股 + 运行日志提示，不推送用户（不是系统故障）。

## 后果

- 抓取开销从「数千请求/轮」降到「≤50 请求/轮」，单轮运行控制在几分钟内。
- 推送量与自选股数量成正比，噪音可控。
- 后续如需扩容，可考虑指数成分股等二级列表，但不在本期范围。
- 改自选股 = 改 GitHub 上的一个 variable，无需 push 代码。
