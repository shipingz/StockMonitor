# ADR-0013: 复盘模式（replay）— flag 触发，回放最近完整交易日的全部信号

- 状态：**已确认**
- 日期：2026-08-15（讨论确认）

## 背景

无状态设计（ADR-0005）下，实时信号推送后无法对账：用户想验证「系统算出的信号是否完整、正确」，尤其在**非交易日**（周末/节假日）复盘最近一个交易日的表现。需要一个与实时监控共用同一套判定逻辑、但可任意时间运行的「信号复盘」能力。

## 决策

1. **触发方式**：`workflow_dispatch` 新增 `replay`（boolean）与 `replay_date`（string，可选）两个输入，仅手动触发，不影响 schedule 定时任务。环境变量 `REPLAY` / `REPLAY_DATE` 注入脚本。
2. **目标日确定**（决策点①，用户确认方案A）：
   - 显式 `replay_date=YYYY-MM-DD` 时直接使用（非法格式 → 报错退出）；
   - 留空时自动：今天为交易日且北京时间已过 15:00 → 回放今天；否则回放今天之前最近的交易日（交易日历 `tool_trade_date_hist_sina`）。
   - 交易日历获取失败且未显式指定日期 → 报错退出（无法确定目标日）。
3. **判定逻辑与实时路径完全一致**（复用 `compute_ma_signal`）：对目标日当天 16 个收盘时刻逐根判定上穿，每根只用「时间 ≤ 该时刻」的K线（**不用未来数据**），保证结果 = 当天实时运行的信号并集，可复现可对账。
4. **消息**（决策点②，用户确认方案A）：推送一条复盘消息到企业微信（与 dry_run 组合时只打印不推送）：
   - 有信号：`## 📊 信号复盘：2026-08-14（周五）` + 信号列表（按时间升序），复用贪心拆分；**去掉偏离字段**（用户明确要求）；
   - 无信号：`当日无上穿信号（检查 N 只 × 16 根K线）`；
   - 日志中每只股票打印全天 16 根明细（`HH:MM close=.. ma=.. cross=Y/N`）供逐根核对。
5. **异常处理**（决策点③，用户确认照旧）：单股抓取失败静默、整轮失败告警、名称缺失告警——与 ADR-0008 一致；目标日无任何股票数据（超出近 5 个交易日保留范围）→ 告警提示。

## 后果

- 非交易日可随时验证最近一个完整交易日的信号完整性，与群里历史推送对照。
- 数据可用性：`stock_zh_a_hist_min_em` 保留近 5 个交易日（≈80 根），回放最近交易日最早一根（9:45）时仍有 ≥61 根历史，满足 MIN_BARS；目标日超出保留范围时告警提示。
- 复盘消息与实时消息同走一个 webhook，格式均为 markdown。
