# ADR-0008: 失败与异常告警策略 — 分级推送

- 状态：**已确认**
- 日期：2026-08-15（讨论确认）

## 背景

无状态设计（ADR-0005）下，运行失败 = 该根K线静默丢失。用户每天查看推送结果，需要能区分「今天没有信号」与「系统坏了」。所有告警走同一个企业微信 webhook（ADR-0007 的消息格式）。

## 决策

按异常严重程度分级：

| 场景 | 行为 | 说明 |
|---|---|---|
| **单只股票抓取失败** | 静默：指数退避重试 3 次后跳过该股，仅写日志 | 单股失败通常是数据源偶发限流，次日自愈；50 只缺 1 只不值得打扰用户 |
| **整轮全部失败** | 推一条告警「⚠️ 监控异常：本轮全部股票抓取失败」 | 说明数据源整体挂了，用户应当知道；重试 3 次仍失败才触发 |
| **交易日历请求失败** | **按交易日继续跑** + 推一条告警「⚠️ 交易日历获取失败」 | 若当天实为节假日，由 ADR-0003 护栏（最新K线距收盘 >15 分钟 → 跳过）兜底，不会误报信号 |
| **严重延迟（护栏触发）** | 推一条告警「⚠️ 检查延迟：最新K线已收盘 X 分钟，本轮跳过」 | job 排队延迟 >15 分钟，该K线已漏检，用户理应知道 |

## 后果

- 用户每天收到的消息只有两类：信号（ADR-0007）或系统告警（本 ADR），零信号零告警 = 当天无上穿信号（正常）。
- 告警消息与信号消息同格式（markdown），可区分标题。
- 告警上限：每轮运行最多 1 条告警（三类告警互斥或合并为一条，避免刷屏——实现时合并为单条）。
