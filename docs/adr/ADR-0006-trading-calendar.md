# ADR-0006: 节假日剔除 — 交易日历判断 + K线新鲜度护栏；调休周末不覆盖（手动跑）

- 状态：**已确认（2026-08-15 修订：交易时段护栏改为「最新已收盘K线日期」判断，修复 15:03 被误杀漏洞）**
- 日期：2026-08-15（讨论确认）

## 背景

cron 只排周一至周五（`1-5`），但 A 股有法定节假日休市（落在工作日）与调休导致的周末开盘。需要决定脚本如何处理非交易日。

## 选项

| 方案 | 行为 | 优点 | 缺点 |
|---|---|---|---|
| A. 交易日历判断 + cron 保持 `1-5` | 脚本启动查交易日历（AKShare `tool_trade_date_hist_sina()`），今天非交易日直接退出 | 简单；非交易日 0 推送 0 告警 | 调休周末（一年约 1~2 次）不监控，信号丢失 |
| B. cron 改每天触发 | 脚本内判断「交易日 + 交易时段」双重检查 | 调休周末自动覆盖 | 非交易日每天 16 次空跑；判断逻辑成为每次运行必走路径，出错面更大 |

## 决策

采用 **A：交易日历判断 + K线新鲜度护栏**（2026-08-15 修订）。

- 脚本启动流程：
  1. 取当前北京时间；
  2. 查交易日历（AKShare `tool_trade_date_hist_sina()`，一次请求拿全年交易日）——今天非交易日 → 直接退出（exit 0，无推送无告警）；
  3. 抓取各股 15 分钟K线后，取「最新一根已收盘K线」按**日期与新鲜度**判断（取代原「当前时间窗口」判断——原方案在 15:03 触发时会被 13:15~15:00 区间排除，导致 15:00 收盘的K线永久漏检，是漏洞）：
     - 最新已收盘K线日期 ≠ 今天 → 直接退出（今天第一根K线 9:45 尚未收盘，正常情况，非告警；覆盖 9:30~9:45 的手动触发）；
     - 日期 = 今天 且 距收盘 ≤15 分钟 → **正常处理**（15:03 触发时最新K线为 15:00 收盘，距收盘 3 分钟 → 正常处理，最后一根K线不遗漏）；
     - 日期 = 今天 且 距收盘 >15 分钟 → 严重延迟，跳过并告警（ADR-0008）。
- **调休周末不覆盖**：用户接受一年约 1~2 天的信号丢失；若当天需要监控，用户手动 `workflow_dispatch` 触发。

## 后果

- 非交易日零噪音（无推送、无告警、无失败日志）。
- 每个交易日 16 轮运行全部覆盖，含 15:03 最后一轮（15:00 收盘K线必被检查）。
- 交易日历请求失败时的兜底策略：按交易日继续跑 + 推告警（ADR-0008）；若当天实为节假日，由「最新K线日期 ≠ 今天 → 退出」兜底，不会误报信号。
