# ADR-0016: 实时价检测模式 — 任意时刻可触发，判定基于实时价 vs MA60（不依赖已完成K线）

- 状态：**已确认（待实现）**——决策已定，实现等用户完成新浪版速度测试后启动
- 日期：2026-08-15（讨论确认；同日修订：从「每 5 分钟检测」澄清为「任意时刻可检测」，频率不是约束，判定基准才是）

## 背景

用户提出：项目不应只依赖「最新一根已收盘 15 分钟K线」做检测。希望**允许在任何时间点运行检测**，判定依据是**当前实时价**与 MA60 的对比——不需要等 15 分钟K线收盘。

- 触发形态：不绑定「K线收盘后 3 分钟」；cron 按需配置（GitHub Actions 最小粒度 5 分钟，可 `*/5` 或自定义时刻），任意时间手动触发同样有效。
- 判定基准：实时价，而非已收盘K线的收盘价。

## 已确认的决策

### 1. MA60 基准保持不变

- MA60 = **最近 60 根已收盘 15 分钟K线收盘价的简单平均**（口径1：含最新已收盘那根，ADR-0002 不变）。
- 60 根 × 15 分钟 = 15 小时 ≈ **3.75 个交易日**（过去 4 天左右的交易均价）。
- 未收盘K线没有收盘价，不进窗口。
- **关键推论**：MA60 只随 K 线收盘滚动。任意两次检测之间若无新K线收盘，**MA60 是常数**；新K线收盘后才滚动。

### 2. 无状态上穿判定（锚点法，实时价版）

```
上穿 = 上一根已收盘15分钟K线收盘价 ≤ MA60  <  当前实时价
```

- 锚点：**上一根已收盘K线**——「价格最近一次定格时在均线下方」就是「之前低于」的证据。
- 当前实时价 > MA60 = 「现在高于」。
- MA60 在无新K线收盘期间是常数 → 这是一次完整的从下到上穿越，**无需跨检测记忆状态**（延续 ADR-0005 无状态设计）。
- 每次检测所需数据（60 根历史 + 上一根已收盘K线 + 实时价）全部来自本轮抓取。

### 3. 交易时段护栏（实时价模式新增要求）

实时价在**非交易时段是停滞的最后成交价**（午休、盘前、盘后），无新成交则检测无意义且会重复误报。因此实时价判定仅在交易时段内执行：

- 仅当当前北京时间处于 9:30–11:30 / 13:00–15:00 区间时才做实时价对比；
- 非交易时段运行则直接退出（0 推送，与 ADR-0006 语义一致）。

### 4. 重复推送：接受（方案 A）

- 同一根「锚点K线」在无新K线收盘期间会被多次检测复用，若实时价持续 > MA60，**同一上穿事件会重复推送**（推送次数与检测频率相关：5 分钟粒度下最多约 3 次）。
- 用户确认接受重复（**A 方案**），不引入状态去重（B）与时间窗口过滤（C，有 job 延迟漏检风险）。
- 消息携带锚点K线时间戳，重复消息可人工识别。

## 与原「K线收盘确认」模式的关系

- **实时价模式（本 ADR）**：任意时刻触发，判定 `锚点收盘价 ≤ MA60 < 实时价`，信号可提前至价格越线时刻。
- **K线收盘模式（ADR-0002/0003）**：每根K线收盘后判定 `prev_close ≤ prev_ma < cur_close`（均线各自时刻），语义保留。
- **复盘模式（ADR-0013）**：实时价不可回放，复盘仍基于 K 线收盘判定（与历史实时运行结果对齐）。实时价模式的「锚点+实时价」事件无法事后精确复现，复盘中以对应 K 线收盘判定近似。

## 待实现清单（未实现，等速度测试结果）

1. **cron 改交易时段 5 分钟粒度**（或按需时刻）：`*/5` 覆盖 9:30–11:30 / 13:00–15:00（约 48 轮/天），修订 ADR-0003。
2. **单轮提速**：若触发频率提高，串行 + 2~5s 限速（50 只 3~5 分钟/轮）不可行 → **并发抓取**（修订 ADR-0011；新浪对并发容忍度高于东财）。
3. **实时价来源**：复用新浪 `hq.sinajs.cn` 批量接口（现仅取名称，多解析「最新价」字段即可），50 只 1 次请求。
4. **判定逻辑**：`compute_ma_signal` 增加实时价版 `prev_close ≤ MA60 < 实时价`。
5. **护栏**：ADR-0006 的「最新K线必须今天」保留 + 本 ADR 新增「交易时段」护栏。
6. **消息**：实时价模式消息标注锚点K线时间戳与检测时刻。

## 后果

- 信号时效性从「K线收盘后 3 分钟 + 运行」提前到「价格越线后 ≤ 检测粒度」。
- 同一信号重复推送次数与检测频率成正比，消息带锚点时间戳。
- 单轮请求量不变（50 次 K线 + 1 次实时价），并发化后运行时间显著缩短。
- 实现前需用户完成两件事：① 新浪版全流程速度实测（确认单轮耗时上限）；② 确认调度形态（如 48 轮/天）可接受。
