# ADR-0003: 调度方式 — 交易时段每 5 分钟轮询 + 实时价判定（v3，取代精确对齐）

- 状态：**已确认**
- 日期：2026-08-15（确认）；v2 2026-08-15；**v3 2026-08-15（当前）**

## 修订记录

- v3（当前）：交易时段每 5 分钟轮询（约 48 轮/天），配合实时价判定（ADR-0016）与并发抓取（ADR-0011 修订）。
- v2（已废弃）：收盘后 3 分钟精确对齐，16 时刻显式 cron，无状态（ADR-0005）。
- v1（已废弃）：每 5 分钟轮询 + 跨运行去重状态。

v2→v3 原因：用户确认实时价模式（ADR-0016）——任意时刻检测、判定基于实时价 vs MA60，不再依赖「K线收盘后 3 分钟」触发；单轮提速（并发，ADR-0011）与数据源切换（新浪，ADR-0015）使 5 分钟粒度在耗时上可行（34 只 1 分 12 秒，全部任务 2 分钟内）。

## 背景

GitHub Actions 的 `schedule` cron 最小粒度 5 分钟，触发不保证准时（高负载时段延迟最严重），schedule 运行失败不自动重试。实时价模式要求检测频率 ≥ 数据变化频率（15 分钟K线内多次检测才有提前预警意义）。

## 决策（v3）

1. **cron（UTC，北京时间 = UTC+8）**：
   - `*/5 1-3 * * 1-5`（北京 9:30–11:55）
   - `*/5 5-7 * * 1-5`（北京 13:00–15:55）
   - 精确裁剪由脚本护栏完成：非交易时段（9:30 前 / 15:10 后）退出（ADR-0016 `is_trading_time`）；9:30–9:45 由「最新已收盘K线必须是今天」拦截（ADR-0006）；午休（11:30–13:00）cron 本就不触发。
2. **每轮判定**：实时价 vs MA60（锚点法，ADR-0016）；无信号推心跳（ADR-0010）。
3. **重复推送接受**（ADR-0016 方案 A）：同一锚点K线窗口内最多约 3 次检测复用，同一信号重复推，消息带锚点K线时间戳识别。
4. **护栏保留**：最新K线日期必须今天；严重延迟（>15 分钟）告警跳过；交易日历剔除节假日；调休周末手动触发。
5. workflow 保持 `concurrency` 组防并发重叠；`workflow_dispatch` 手动触发（dry_run/force_run/replay）。

## 后果

- 信号时效从「K线收盘后 3 分钟」提前到「价格越线后 ≤ 检测粒度（5 分钟）」。
- 运行次数从 16 轮/天增至约 48 轮/天；公有仓库额度免费（ADR-0003 前提）。
- 同一信号最多重复约 3 次，消息带锚点时间戳人工识别。
- 单轮耗时：6 只 ≈ 15 秒、34 只 ≈ 1 分 12 秒（实测），50 只上限 ≈ 2 分钟内。
