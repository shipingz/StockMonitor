# ADR-0010: 每轮心跳推送 — 无信号也推送「系统正常」确认

- 状态：**已确认**
- 日期：2026-08-15（讨论确认）

## 背景

原设计（ADR-0008）为「零信号零告警 = 正常」。用户提出：希望每 15 分钟运行一次时，即使没有信号也推送一次，作为系统正常运行的可感知确认。

## 决策

每轮运行（交易日 16 次/天）**必推且只推一条消息**，三态互斥：

| 状态 | 消息形态 | 对应 ADR |
|---|---|---|
| 有信号 | 信号消息（合并推送） | ADR-0007 |
| 无信号 | ✅ 心跳：`系统正常 | K线时间 HH:MM | 检查 N 只 | 0 信号` | 本 ADR |
| 异常 | ⚠️ 告警（整轮失败/日历失败/严重延迟） | ADR-0008 |

- 心跳消息是**健康探针**：某轮未收到消息 ⇒ 管道故障（job 挂、webhook 失效、workflow 被禁用），用户可感知。
- 消息噪音：16 条/天（仅交易日），用户明确接受此噪音水平。
- 企业微信限制（20 条/分钟）远未触及。

## 定稿细节（2026-08-15）

1. **不设每日收市总结**：15:03 最后一轮的心跳即收市确认，不重复推送。
2. **周末/节假日不推**：沿用 ADR-0006，非交易日 0 推送。语义：某天完全无消息 = 非交易日 或 系统故障。
3. **15:03 最后一轮必须执行**：由 ADR-0006 修订后的「最新已收盘K线日期」护栏保证（15:00 收盘K线距触发 3 分钟 ≤ 15，正常处理），确保收市心跳与 15:00 信号不漏。

## 后果

- 「某天完全没有消息」的语义 = 非交易日 或 系统故障，二者可进一步通过查看 Actions 运行记录区分。
- 信号消息与心跳消息同走一个 webhook，格式均为 markdown。
