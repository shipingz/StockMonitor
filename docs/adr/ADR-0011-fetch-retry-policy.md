# ADR-0011: 数据抓取容错策略 — 适度并发（默认 3 线程）+ 每线程限速 + 重试

- 状态：**已确认（2026-08-15 修订：从纯串行改为适度并发，为 ADR-0016 实时价模式铺路）**
- 日期：2026-08-15（讨论确认）；2026-08-15 修订

## 背景

每轮 ≤50 次 15 分钟K线请求（+ 1 次名称表 + 1 次交易日历）。数据源以新浪为主（ADR-0015），东财兜底。用户指示重试策略照抄参考项目 [ZhuLinsen/daily_stock_analysis](https://github.com/ZhuLinsen/daily_stock_analysis)；修订：串行在实时价模式（ADR-0016，任意时刻可检测）下单轮耗时不可接受，改为适度并发。

## 参考项目的做法（已核对其源码，作为基础保留）

- 原为串行：默认 `MAX_WORKERS=1`，不并发。
- **限速**：每次请求前随机 sleep 2~5 秒（`_enforce_rate_limit`）。
- **重试**：历史数据抓取 tenacity `stop_after_attempt(3)` + `wait_exponential(min=2, max=30)`——共 3 次尝试，指数退避。
- 失败处理：单只股票失败记日志，不中断整体流程。

## 决策（2026-08-15 修订）

1. **适度并发**：`FETCH_WORKERS`（环境变量，默认 3，范围 1~8；设 1 即退化为纯串行）。
   - 实测（新浪源，本机）：6 只串行 34s → 3 线程 11.4s（约 3 倍）；50 只推算 ≈ 95s，满足 5 分钟粒度。
   - 安全依据：串行限速 2~5s 的本质是控制总 QPS ≤ 0.5；3 线程每线程独立限速后总 QPS ≈ 1.5，新浪源承受力远高于此（其快照接口单次返回 5400 只）。东财仅兜底路径出现（当前被风控基本不走），风险可忽略。
2. **每线程独立限速**：`enforce_rate_limit` 改用 `threading.local` 保存各线程上次请求时间——并发下总 QPS 由线程数线性控制，不因并发突破单线程节奏。
3. **重试不变**：每只最多 3 次尝试，指数退避 `min(2**attempt, 30)`；单股失败静默跳过（ADR-0008），整轮失败告警。
4. **并发安全**：东财 nid 缓存加 `threading.Lock`——仅首个线程请求令牌，其余等锁命中缓存（20s 成功 / 5min 失败），避免并发重复请求被风控的 anonflow2。
5. 失败处理与 ADR-0008 衔接不变；单轮请求量不变（≤50 次 K线 + 1 名称 + 1 日历）。

## 后果

- 单轮耗时：6 只 ≈ 11s，50 只 ≈ 1.5 分钟（3 线程、新浪源）——实时价模式（ADR-0016）可行。
- 总 QPS ≈ FETCH_WORKERS/3.5s，由线程数显式控制；默认 3 为安全与速度的平衡点，可通过 `FETCH_WORKERS` 调整（2~4 均可，经用户确认）。
- 429/失败风险由限速 + 退避重试共同消化；新浪源并发实测无异常。
- 注：`main.py` 中通过环境变量 `FETCH_ATTEMPTS`（默认 3）、`FETCH_SLEEP_MIN/MAX`（默认 2/5）、`FETCH_WORKERS`（默认 3）可调。
